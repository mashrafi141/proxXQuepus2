# ProxXQuepus v1.0.2 Changelog

## Release identity

- `versionName`: `1.0.2`
- `versionCode`: `3` (incremented from `2`)
- `applicationId`, namespace, signing configuration and branding unchanged.

## Added

### Storage modes

- New persisted Storage Mode setting with `Local Mode` default and `Cloud Mode`.
- Storage-mode selector in both local and cloud Settings.
- Local scan is paused when switching to Cloud Mode; local state is not modified.
- Cloud state uses separate DataStore preferences.

### TeraBox Cloud Mode

- Isolated `com.example.cloud` package tree.
- Official TeraBox Open Platform flow:
  - official Android code return to `proxxquepus://terabox-oauth`, followed by backend exchange;
  - backend-managed token info, refresh and optional HTTP callback/claim flow;
  - signed OAuth state;
- Android Keystore AES-GCM encrypted token storage (no plaintext tokens).
- Multiple connected accounts with per-account tokens and root selection.
- Cloud Setup, reconnect, account management, root picker, browse, collections, search, viewer and settings screens.
- Cached cloud folder metadata, pagination, search and offline fallback.
- Cloud media type filters, sorting, multi-selection, favourites, recent history and playback position.
- Dedicated Coil thumbnail loader with bounded memory/disk cache and stable cache keys.
- Cloud photo viewer with pinch/pan, GIF viewer, and video playback using official direct dlink with HLS fallback.
- User-initiated download to a SAF destination.
- Rename/delete via the official file manager API with confirmation (unverified live).
- Cloud cache clear that never deletes remote TeraBox files.

### Backend

- `backend/` FastAPI service with `/health`, auth start/callback/claim/refresh and status endpoints.
- Environment-based configuration, signed state, one-time claim store, rate limiting, timeouts, retries, redacted logs and no media proxy.
- Normal Render Web Service start requirements/scripts and setup documentation.

### Documentation

- `docs/CLOUD_MODE_ARCHITECTURE.md`
- `docs/TERABOX_API_VALIDATION.md`
- `docs/RENDER_BACKEND_SETUP.md`
- `backend/README.md`

## Changed

- Settings screen shows `1.0.2` from `BuildConfig` instead of a stale hardcoded version.
- GitHub Actions release workflow derives the release tag from the pushed tag or workflow input, defaults to `v1.0.2`, and no longer hardcodes a `v1.0.1` APK filename.
- Local `VideoPlayerController.setSource` accepts an optional MIME type for the cloud HLS fallback; existing local callers are unchanged.
- Local `MainViewModel` gains a `pauseScan()` helper used only when switching to Cloud Mode.

## Not changed

- Local scanner, local repository, local file manager, local thumbnail engine, local Room schema/version and local database data.
- Existing Local Mode UI, gestures, security lock, sorting, search, collections, favourites and playback history.
- Local root folder selection and persisted local state.
- App identity, namespace and signing behavior.

## Known limitations / blocked items

- No TeraBox developer credentials, approval or authorized test account were available. Live OAuth, listing, playback, Range/seek, thumbnails and file operations remain unverified live.
- Cloud upload and move/copy are not exposed in v1.0.2.
- TeraBox's application-folder restriction may limit which folders can be browsed.
- Backend is Render Free-compatible; tokens/claims are memory-only and lost on restart/sleep.
